# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The scaffold, generated by `rebar3 new hecate_service`: an OTP release that
  boots on `hecate_om`, joins the mesh, and answers `/health` on 8490.
- `hecate_tube_service`, the six-callback `hecate_om_service` contract,
  announcing all four of this service's mesh capabilities
  (`tube.lookup_channel`, `tube.lookup_video_clip`, `tube.lookup_content`,
  and `tube.watch_video_clip` with `kind => streamer`), all advertised
  generically by `hecate_om:boot/1` via `hecate_om_capabilities` (requires
  `hecate_om >= 0.18.0` for the streamer capability kind), and requesting
  no realm authority, since none of its capabilities are pubsub-scoped.
- Unit tests asserting the contract's shape, including that the mesh-facing name
  and the reported version match the application's own.
- `Containerfile` building an alpine image, with macula's QUIC NIF compiled from
  source rather than fetched against a foreign libc.
- `deploy/docker-compose.yml`, the service's own run contract.
- CI: `lint-and-test` on every push and pull request, `build-and-push` to
  the registry on `main` and on `v*` tags, publishing both `:latest` and the semver
  tag.

### Fixed

- All four mesh capabilities' advertisements now carry `hecate_om_capabilities`'s
  curated `ttl_ms` (4x its 30s republish interval), instead of one of them
  (`tube.watch_video_clip`, before it migrated onto `capabilities/0`) silently
  falling back to `macula_record`'s ~48h envelope default -- a dead tube
  instance's advertisement now ages out of the DHT in minutes rather than
  days, like every other hecate-service. Needs `macula >= 10.11.1` (bumped
  10.10.0 -> 10.14.4), below which `macula_direct_dial:adv_opts/1` dropped
  `ttl_ms` even when passed.
- The `tube.lookup_channel` and `tube.lookup_video_clip` replies, and the
  `channel_announced_v1`, `video_clip_published_v1` and
  `video_clip_retracted_v1` facts, send names, descriptions, owners, tags
  and the announcement's `action` as CBOR text (`{text, Bin}`) instead of
  byte strings, so non-BEAM consumers (macula-mcp, macula-cli, the SDKs)
  get strings. Ids and mcids stay bytes. (hecate-tube#2)
- `tube.watch_video_clip`, `tube.lookup_channel` and `tube.lookup_video_clip`
  read their id through `hecate_om_wire:field/2` instead of matching an atom
  key, and unwrap an id sent as text. macula's decoder makes a key an atom
  only when that atom is already loaded, so an atom-only match depended on
  load order. `field/2` finds the binary form today; the `{text, Bin}` form a
  missing atom produces needs the hecate_om release with hecate-om#1.
  (hecate-tube#3)
- CI: `lint-and-test` installs a Rust toolchain. macula's
  `macula_cbor_nif` compile hook fails the build without cargo rather than
  skip.

### Removed

- `tube_mesh_providers.erl`, the hand-rolled `gen_server` that advertised
  this service's mesh capabilities directly via `macula_response`/
  `macula_streamer:advertise_direct` -- see
  `hecate-corpus/skills/antipatterns/structure.md`, Demon 59. Superseded by
  `hecate_tube_service:capabilities/0`, advertised generically by
  `hecate_om:boot/1`.
